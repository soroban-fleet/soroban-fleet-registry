# STRIDE Threat Analysis Matrix

This matrix applies the Microsoft STRIDE methodology to the Soroban Fleet Registry service architecture.

---

| Threat ID | STRIDE Category | Target Asset / Surface | Threat Description | Likelihood | Impact | Existing Mitigation in V1 | Residual Risk | Monitoring Signal & Planned Response |
|---|---|---|---|---|---|---|---|---|
| **TH-01** | **Spoofing** | REST API Endpoints | Malicious client attempts to spoof administrative origin or bypass origin checks. | Low | Low | API is strictly read-only; no administrative mutation endpoints exist. CORS headers restrict browser origins. | Low risk of client confusion | Monitor unexpected `Origin` headers; reject unsupported CORS preflight requests. |
| **TH-02** | **Tampering** | Checkpoint & Database State | SQL injection or unauthorized database modification alters indexed fleet membership or checkpoint height. | Very Low | High | Parameterized queries used exclusively throughout repository (`database/sql` positional placeholders); no string concatenation in SQL. | Zero SQL injection identified; database restricted to private network | Alert on database error logs; daily automated database dumps; two-way migration tests. |
| **TH-03** | **Tampering** | RPC Ingestion Stream | Man-in-the-middle attack modifies raw ledger entries returned by upstream Soroban RPC. | Low | High | Upstream queries use HTTPS/TLS exclusively. Checksum and XDR deserialization validation fails on corrupted payloads. | Compromise of public RPC node | Alert on RPC deserialization errors (`XDR decode failed`); support configuring trusted internal Soroban RPC endpoints. |
| **TH-04** | **Repudiation** | Verification Audits | Client or maintainer disputes historical verification status claim. | Low | Low | Verification runs are recorded with audit timestamps, target owner, tag, expected WASM, resolved hash, and observed ledger checkpoint. | None (audits are append-only) | Store verification run records in `fleet_verifications` table with timestamped ledger sequence. |
| **TH-05** | **Information Disclosure** | Environment & Database Credentials | Database credentials (`SFR_DATABASE_URL`) or server logs leaked via API error responses or stack traces. | Low | High | API error handler normalizes internal errors into generic RFC 7807/JSON envelopes; internal database errors masked from client responses. | Accidental container log exposure | Restrict container log permissions; audit logs to ensure credentials are masked in debug outputs. |
| **TH-06** | **Denial of Service** | Public API Service | High-volume request bursts (e.g. rapid calls to `/verify` or unindexed queries) exhaust server resources. | Medium | Medium | In-memory verification utilizes batching (`BatchSize: 50`); database queries are indexed by `(owner, tag)` and `contract_id`. | Resource exhaustion under DDoS | **Planned in Tranche 1**: Configurable IP rate-limiting middleware (Issue #11) and reverse proxy limits. |
| **TH-07** | **Denial of Service** | Indexer Pipeline | Upstream Stellar RPC outage causes indexer stalls or excessive reconnection thrashing. | Medium | Medium | Linear backoff retry logic; checkpoint only advances after successful database commit; pipeline halts safely on persistent RPC failure. | Ingestion lag increases during network outages | Metric `INDEXER_LAG_LEDGERS` fires alert when checkpoint lags > 100 ledgers behind latest network ledger. |
| **TH-08** | **Elevation of Privilege** | Container / Runtime | Attacker exploits dependency vulnerability to gain shell execution within the container. | Low | High | Minimal Alpine Linux base images; unprivileged non-root user execution in production container; no shell binaries required for Go runner. | Third-party dependency CVEs | Automated GitHub dependency vulnerability alerts; Dependabot PRs; reproducible Docker builds. |
